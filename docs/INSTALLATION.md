# 📥 Panduan Instalasi Lokal (Lokal Setup)

Dokumen ini menjelaskan langkah-langkah untuk menyiapkan dan menjalankan proyek **Futaba Digital Document Management System** di lingkungan pengembangan lokal Anda.

---

## 📋 Prasyarat Sistem

Pastikan perangkat Anda memenuhi persyaratan software berikut sebelum memulai:

- **Node.js**: Versi `18.x` atau lebih baru (direkomendasikan versi LTS terbaru).
- **pnpm**: Sistem manajemen paket yang digunakan untuk mengelola dependencies proyek.
- **Akun Supabase**: Dibutuhkan untuk database PostgreSQL dan penyimpanan file (Storage).

---

## 🚀 Langkah-langkah Setup Lokal

### 1. Kloning Repositori
Kloning repositori proyek dari Github ke mesin lokal Anda:
```bash
git clone https://github.com/mahesarahdintyo/Futaba-Project.git
cd Futaba-Project
```

### 2. Instalasi Dependencies
Instal semua package dependencies yang diperlukan menggunakan pnpm:
```bash
pnpm install
```

### 3. Konfigurasi Environment Variables
Buat file baru bernama `.env.local` di direktori utama (root) proyek dan isi variabel berikut:
```env
# Supabase URL & Anon Key (Dapat ditemukan di Settings > API pada dashboard Supabase)
NEXT_PUBLIC_SUPABASE_URL=https://your-project-id.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-supabase-anon-key

# Service Role Key (Dibutuhkan untuk beberapa operasi backend dengan hak akses penuh)
SUPABASE_SERVICE_ROLE_KEY=your-supabase-service-role-key
```

### 4. Konfigurasi Supabase Backend

#### A. Membuat Tabel Database
Buka SQL Editor di dashboard Supabase Anda, lalu buat tabel-tabel berikut:

##### 1. Tabel `lands`
```sql
CREATE TABLE public.lands (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);
```

##### 2. Tabel `folders`
```sql
CREATE TABLE public.folders (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name TEXT NOT NULL,
  parent_id BIGINT REFERENCES public.folders(id) ON DELETE CASCADE,
  land_id TEXT REFERENCES public.lands(id) ON DELETE CASCADE NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);
```

##### 3. Tabel `categories`
```sql
CREATE TABLE public.categories (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name TEXT UNIQUE NOT NULL,
  description TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- Pre-populate kategori default
INSERT INTO public.categories (name, description) VALUES
('SOP', 'Standard Operating Procedures'),
('Manual', 'User Manuals and Guides'),
('Form', 'Forms and Templates'),
('Lainnya', 'Other Documents');
```

##### 4. Tabel `documents`
```sql
CREATE TABLE public.documents (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  title TEXT NOT NULL,
  description TEXT,
  category_id BIGINT REFERENCES public.categories(id) ON DELETE SET NULL,
  file_name TEXT NOT NULL,
  file_path TEXT NOT NULL,
  file_size BIGINT,
  file_type TEXT,
  uploaded_by TEXT,
  target_time TIMESTAMP WITH TIME ZONE,
  hidden_from_operator BOOLEAN DEFAULT false NOT NULL,
  folder_id BIGINT REFERENCES public.folders(id) ON DELETE CASCADE,
  land_id TEXT REFERENCES public.lands(id) ON DELETE CASCADE,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL,
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);
```

##### 5. Tabel `land_display_documents`
```sql
CREATE TABLE public.land_display_documents (
  land_id TEXT PRIMARY KEY REFERENCES public.lands(id) ON DELETE CASCADE,
  document_id UUID REFERENCES public.documents(id) ON DELETE SET NULL,
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()) NOT NULL
);
```

#### B. Menjalankan Migrasi Tambahan
Terapkan file SQL tambahan yang berada di folder [supabase/migrations](file:///c:/laragon/www/Futaba-Project/supabase/migrations) ke SQL Editor Supabase Anda sesuai urutan tanggal pembuatannya.

#### C. Konfigurasi Storage Bucket
1. Buka menu **Storage** di dashboard Supabase.
2. Buat bucket baru bernama `documents`.
3. Set bucket tersebut sebagai **Public** agar operator/klien dapat mengambil file dengan cepat (namun kita juga menggunakan Signed URL di backend untuk keamanan opsional).
4. Buat policy akses pada bucket `documents` untuk mengizinkan operasi read, insert, dan delete:
   - **Read Access**: Allow for `public` (anyone).
   - **Write & Delete Access**: Diizinkan untuk semua selama tahap pengembangan, namun disarankan membatasi hanya untuk authenticated users pada tahap produksi.

## 💻 Menjalankan Server Pengembangan

Setelah semua langkah di atas diselesaikan, jalankan server Next.js lokal:
```bash
pnpm dev
```
Aplikasi akan berjalan dan dapat diakses melalui browser Anda di alamat:
**[http://localhost:3000](http://localhost:3000)**
